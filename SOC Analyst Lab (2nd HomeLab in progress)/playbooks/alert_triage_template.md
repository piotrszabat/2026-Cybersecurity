# Alert Triage Template

## Purpose

This template is used to perform consistent first-level SOC alert triage.

The objective is to determine:
- what happened
- who or what is affected
- whether the alert is a true positive or false positive
- what immediate next steps are required

## 2. What Happened?

Multiple Windows authentication events were detected on host **PC01**, including failed and successful logon attempts. The activity was identified using a Splunk search query targeting Windows Security Event Logs.

The alert was triggered based on the following query:
index=* sourcetype="WinEventLog:Security" (EventCode=4625 OR EventCode=4624)
| eval user=coalesce(Account_Name, TargetUserName)
| eval src=coalesce(IpAddress, Source_Network_Address, Workstation_Name, "unknown")
| transaction user, src maxspan=10m
| search EventCode=4625 EventCode=4624
| table _time user src EventCode host

---

- **EventCode 4624:** Successful logon event also present  
- Activity occurred within a short time window (last 15 minutes)

## 8. Lessons Learned

- Alert is useful for identifying failed authentication attempts  
- Detection logic may be too sensitive for low-volume events  
- Recommend implementing threshold-based alerting (e.g., multiple failures within a time window)  
- Additional context (e.g., asset criticality, user role) would improve triage efficiency  
- Consider tuning alerts to reduce noise in lab or testing environments
